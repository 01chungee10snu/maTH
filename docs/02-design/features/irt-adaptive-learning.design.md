# IRT 기반 적응형 학습 설계

## 목적

정답률만으로 난이도를 올리고 내리는 방식에서 벗어나, 문항 난이도와 학습자 현재 상태를 함께 추정해 다음 문제를 제시한다. 초기 운영 모델은 Rasch/1PL IRT이며, 문제 수와 응답 로그가 충분히 쌓이기 전까지는 수동 난이도 태깅을 기준으로 한다.

## MVP 모델

- `theta`: 학습자 능력 추정치, 기본값 0, 범위 -3~3
- `b`: 문항 난이도, 수동 태깅, 범위 -3~3
- `P(correct) = 1 / (1 + exp(-(theta - b)))`
- 다음 문항은 `IrtLearningPolicy`가 학습 목적에 따라 고른다.
- 진단 단계에서는 아직 관찰이 부족한 skill을 넓게 측정한다.
- 약점 보강 단계에서는 mastery가 낮은 skill을 적정 성공확률 문항으로 연습한다.
- 숙달 확인 단계에서는 약간 도전적인 문항으로 안정성을 확인한다.
- 최근 출제 문항은 강한 재출제 penalty를 둔다.

## IRT 학습 촉진 정책

문항 선택은 단순히 `theta`와 가장 가까운 난이도를 고르는 방식이 아니다. 앱은 아래 단계 중 하나를 판단하고 문항 효용 점수를 계산한다.

| 단계 | 진입 조건 | 출제 목적 |
| --- | --- | --- |
| `diagnostic` | 누적 12문항 미만 또는 표준오차 큼 | 다양한 skill을 넓게 측정해 초기 theta와 약점 후보를 안정화 |
| `targeted_practice` | 2회 이상 관찰된 skill mastery가 0.65 미만 | 약점 skill을 너무 어렵지 않은 문항으로 반복 보강 |
| `adaptive_practice` | 진단은 지났지만 숙달 확인 전 | 정보량, 난이도, skill 커버리지, 반복 억제를 균형화 |
| `mastery_check` | 30문항 이상, 표준오차 낮음 | 약간 도전적인 문항으로 숙달 유지 여부 확인 |

정책 결과는 문항의 `selection_policy`와 풀이 로그의 `learning_phase`, `target_skill`, `selection_utility`에 남긴다. 부모 리포트는 현재 학습 정책 설명을 함께 보여준다.

## 힌트와 사고 단계 반영

정답 여부를 0/1로만 보지 않는다.

| 풀이 결과 | IRT 반영 |
| --- | --- |
| 무지원 정답 | 1.00 |
| 낮은 힌트 정답 | 0.84~0.92 |
| 높은 힌트 정답 | 0.45~0.60 |
| 오답이지만 일부 사고 단계 성공 | 0.00~0.35 |
| 완전 오답 | 0.00 |

관계수학 코치에서는 `base`, `direction`, `visualization`, `operation`, `explanation` 단계 성공률을 `stepSuccessRate`로 넣는다.

## 문제 확장 규칙

새 문제를 추가할 때 최소 필드는 다음과 같다.

```json
{
  "problem_id": "REL_MATH_006",
  "grade_band": "G1_G2",
  "level": 5,
  "skill_tags": ["UNIT_COMPARE", "DIRECTION_CONFUSION"],
  "irt": { "model": "rasch", "b": 0.2 },
  "problem_types": ["UNIT_COMPARE"],
  "question": "...",
  "base_unit": "...",
  "entities": [],
  "question_type": "LARGEST",
  "operation": "관계 비교",
  "answer": "...",
  "explanation": "..."
}
```

운영 초기는 `b`를 수동으로 넣고, 응답 로그가 충분히 쌓이면 정답률과 힌트 사용량을 기준으로 재보정한다. 초기 seed 은행은 최소 50문항을 유지하고, 핵심 skill은 각각 최소 3문항 이상을 둔다. 새 단원을 추가할 때는 먼저 10문항 단위로 seed를 넣고, 실사용 로그가 쌓이면 난이도 `b`를 재추정한다.

## 적용 하네스

목표 달성을 위한 운영 하네스는 다음 네 겹으로 둔다.

| 하네스 | 확인 내용 |
| --- | --- |
| Seed bank 변환 하네스 | 1000개 이상 초등 문장제를 IRT 런타임 문항으로 변환하고 `problem_id`, `irt.b`, `skill_tags`, 선택지, coach 단계가 유지되는지 확인 |
| IRT 선택 하네스 | 연속 출제에서 같은 문항 반복을 억제하고, 현재 `theta`에 가까운 문항을 고르되 최근 출제 다양성을 유지하는지 확인 |
| 측정 품질 하네스 | 신뢰도, 타당도, 표준오차, skill 커버리지, 과정 로그 충족 여부를 부모 리포트와 계약 테스트에서 확인 |
| 브라우저 스모크 하네스 | GitHub Pages와 로컬 정적 서버에서 seed bank fetch, 바로학습 시작, IRT 로그, 부모 리포트가 실제로 동작하는지 확인 |

이 하네스가 통과해야만 문항을 추가하거나 난이도 보정 로직을 바꾼다.

## 초등 과정 통합 방식

관계형 문장제는 별도 `관계수학 코치` 모드로 운영하지 않는다. 초등학교 과정 중 관계 사고가 중요한 단원에서만 내부 풀이 레이어로 작동한다.

아이의 기본 진입은 학교급, 학년, 단원 선택이 아니라 `오늘의 문제 시작`이다. 이 버튼은 `AdaptiveLearningFlow.createStartPatch()`를 통해 바로 `quiz` 상태로 전환하고, IRT 상태의 약한 skill 또는 기본 초등 관계 사고 단원을 기준으로 다음 문항을 고른다. 기존 학습 지도는 부모, 교사, 특정 단원 연습을 위한 보조 경로로 유지한다.

초기 적용 단원은 다음으로 제한한다.

- 자연수의 곱셈과 나눗셈
- 분수와 소수의 이해
- 분수의 덧셈과 뺄셈
- 분수의 곱셈과 나눗셈
- 길이, 시각, 시간
- 들이와 무게
- 시간과 길이
- 약수와 배수
- 규칙과 대응
- 비와 비율
- 비례식과 비례배분
- 평균 및 그래프 해석 단원

화면에서는 별도 Add-on처럼 보이지 않게 해당 단원 문제로 제시하고, 내부적으로만 기준량, 방향, 표상, 연산, 설명 단계를 기록한다.

## Supabase 저장 대상

- `math_items`: 운영 문제 은행
- `learning_attempts`: 개별 풀이 로그
- `learner_skill_states`: 학습자별 theta 및 skill mastery

아동 데이터는 보호자 동의와 삭제 정책이 확정되기 전까지 local-first로 유지한다.

## 로컬 우선 풀이 로그 큐

앱은 IRT 업데이트가 일어날 때마다 `taehee-irt-attempt-log` localStorage 큐에 풀이 기록을 남긴다. 이 기록은 Supabase `learning_attempts`에 그대로 매핑될 수 있도록 다음 필드를 포함한다.

| 필드 | 의미 |
| --- | --- |
| `local_id` | 기기 내 임시 로그 ID |
| `learner_id` | 로그인 전 기본값 `local-child` |
| `item_id` | `REL_MATH_###` 문제 ID |
| `topic` | IRT 주제, 초기값 `relationship_math` |
| `skill_tags` | 문항이 훈련하는 관계 추론 skill |
| `selected_answer` | 아이가 고른 답 |
| `correct` | 최종 정답 여부 |
| `hint_level` | 정답 확인 전 사용한 힌트 단계 |
| `step_success_rate` | 기준량, 방향, 시각화 등 사고 단계 성공률 |
| `response_score` | 힌트와 사고 단계를 반영한 IRT 응답 점수 |
| `theta_before`, `theta_after` | 풀이 전후 학습자 능력 추정치 |
| `standard_error_after` | 업데이트 후 추정 오차 |
| `error_type` | 오답일 때 추정한 오개념 코드 |
| `sync_status` | `pending` 또는 `synced` |

Supabase 동기화는 RLS 없이 익명 쓰기 정책을 열지 않는다. 운영 적용 시에는 보호자 동의, 사용자 인증 또는 Supabase 익명 인증, RLS 정책, 삭제 요청 처리 방식을 먼저 확정한 뒤 `pending` 로그만 서버에 업로드하고 성공한 항목을 `synced`로 표시한다.

클라이언트 동기화 함수는 `IrtSync.syncPendingAttempts()`와 `IrtSync.requestSync()`로 분리한다. 풀이 기록은 항상 local-first로 저장하고, Supabase 인증 세션이 있거나 `autoAnonymousAuth`가 활성화되어 익명 인증이 가능한 경우 백그라운드로 업로드한다. 인증 또는 DB 정책 문제로 실패하면 `pending` 상태를 유지하고 다음 풀이 때 다시 시도한다.

## 부모용 수리능력 리포트

IRT 결과는 단정적 진단이 아니라 추정치와 불확실성으로 보여준다. 부모 화면에는 정답률만 표시하지 않고 다음 값을 함께 제공한다.

- `abilityIndex`: theta를 보호자가 읽기 쉬운 1-99 지수로 변환한 값
- `theta`: IRT 기반 현재 수리능력 추정치
- `standardError`: 추정 오차
- `confidenceLabel`: 데이터 부족, 관찰 중, 추정 안정화, 안정적
- `independentSolveRate`: 힌트 0-1단계에서 정답을 맞힌 비율
- `weakSkills`: 응답 점수, 힌트 단계, 오답 기록을 종합한 보완 skill
- `recommendations`: 다음 학습 권장 문장

부모 리포트는 `MathAbilityReport.buildParentReport()`에서 생성한다. 초기 버전은 로컬 IRT 로그를 기반으로 계산하고, Supabase 인증과 보호자 동의가 붙으면 학습자별 누적 리포트로 확장한다.

## 신뢰도와 타당도 확보 기준

앱은 수리능력 추정치를 곧바로 확정 판정으로 사용하지 않는다. `MeasurementQuality.evaluate()`가 풀이 로그, IRT 상태, 운영 문제 은행을 함께 평가해 리포트에 해석 가능 범위를 붙인다.

### 신뢰도 기준

| 기준 | 운영 의미 |
| --- | --- |
| 누적 문항 수 | 8문항 미만은 관찰 단계, 30문항 이상부터 개인 추세 해석 가능 |
| 표준오차 | `0.55` 초과는 주의, `0.40` 이하에서 안정적 해석 가능 |
| 반복 skill 측정 | 같은 skill이 3회 이상 반복된 영역이 늘어야 약점 판단 가능 |
| 문항 다양성 | 같은 문항 반복이 아니라 서로 다른 문항으로 추정해야 함 |
| 과정 로그 | 힌트 단계와 응답 점수가 함께 기록되어야 해석 가능 |

### 타당도 기준

| 기준 | 운영 의미 |
| --- | --- |
| 내용타당도 | 핵심 관계 사고 skill별 최소 3문항 이상 보유 |
| 구성타당도 | 모든 문항에 `skill_tags`, `problem_types`, Rasch `b` 값 보유 |
| 과정타당도 | 기준량, 방향, 시각화, 연산, 설명 단계 성공률을 로그로 남김 |
| 학년 범위 | 초등 저학년, 중학년, 고학년 문제를 모두 포함 |
| 해석 제한 | 표준화 검사, 학년 수준 확정, 타 아동 비교에는 사용하지 않음 |

부모 리포트에는 신뢰도 점수, 타당도 점수, 경고 문구, 사용 가능한 해석과 사용하면 안 되는 해석을 함께 둔다. 이 장치는 “정확한 점수”를 과장하기보다, 어떤 조건이 충족될 때 더 신뢰로운 학습 추천이 되는지를 보여주는 품질 관리 레이어다.
